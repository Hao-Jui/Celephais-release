# Celephais
## Spectral XCTS initial-data solvers for numerical relativity

Celephais is a numerical-relativity code built on the
[Kadath](https://kadath.obspm.fr/) spectral library for production
**initial-data** solves in compact-object numerical relativity. It is a sibling
of FUKa rather than a fork of it.
It assembles the Jacobian of nonlinear elliptic (XCTS) systems on a multi-domain
spectral grid and drives an MPI Newton iteration backed by the MUMPS sparse
direct solver (or a dense ScaLAPACK fallback).

It solves the eXtended Conformal Thin-Sandwich (XCTS) equations for isolated and
binary compact objects, in general relativity and in two modified-gravity
theories.

### Solvers included

| Family | Apps |
|--------|------|
| Isolated black hole | `BH` (3D), `BH2d` (2D) |
| Isolated neutron star | `NS` (3D), `NS_nosym`, `NS2d`, `NS2d_xcts` |
| Binary neutron star | `BNS`, `BNS_nosym` |
| Black-hole–neutron-star | `BHNS` |

(`_nosym` variants drop the orbital-plane symmetry for spinning/tilted
configurations. Binary black holes are built on the `BH` formalism via
`bbh.hpp`.)

## Build

### Prerequisites

- CMake ≥ 3.25
- **Ninja** — build generator, wired into all presets
  - macOS: `brew install ninja` · Linux: `apt install ninja-build` (or dnf/pacman)
- **ccache** — compile cache for fast incremental rebuilds
  - macOS: `brew install ccache` · Linux: `apt install ccache`
- C++20 compiler (GCC 10+, Clang 12+)
- MPI (Open MPI, Intel MPI, MPICH)
- BLAS/LAPACK and ScaLAPACK (MKL for example)

MUMPS 5.9.0 and METIS 5.1.0 are **vendored** under `third_party/` and built
automatically as part of the normal build — no separate installation or
`MUMPS_DIR` needed.

### Quick start

Register your machine once, then build with a single command:

1. **Add a preset** for it in `CMakePresets.json` — inherit from `base` and copy
   an existing entry (`macbook` for a PC/workstation, `viper` for a module-based
   HPC). The machine presets already set `BUILD_APPS=ON`.
2. **HPC only:** add `cmake/env/<name>.sh` with the `module load` lines your
   cluster needs. A PC/workstation with the toolchain on `PATH` needs no env script.

Then build the library + apps:

```bash
./compile.sh <name>
```

`./compile.sh` sources `cmake/env/<name>.sh` if present, then configures and
builds via your preset. With no argument it autodetects common hosts (macOS →
`macbook`, else by hostname) and falls back to a generic `env` preset; add a case
to `detect_target` in `compile.sh` to wire autodetection for a new host.

For the `unit`/`smoke`/`eos` tests, configure with `-DBUILD_TESTING=ON` (see
[Testing](#testing) below).

**Prefer an AI agent?** Hand [`soliv_agent.md`](soliv_agent.md) to your coding
agent — it's an install contract that walks it through environment setup,
preflight, build, and (on a cluster) generating the submission template.

## Running a solver

Each app (built with `-DBUILD_APPS=ON`) produces a binary at
`apps/<App>/bin/Release/solve` and a universal launcher symlinked at
`apps/<App>/sbatch_outputs/sub_Celephais.sh` (created by `compile.sh`).

The launcher submits a prepared scripts on a slurm machine, while it
runs locally via `mpirun`.

```bash
cd apps/BH2d/sbatch_outputs
./sub_Celephais.sh initial.toml               # local → mpirun · cluster → sbatch
```

Example input toml file can be generated by dry run `apps/<App>/bin/Release/solve`.
The runtime finds the project root via a compile-time path;
override with `HOME_CELEPHAIS=/abs/path`.

Solver behaviour is tuned through the environment variables catalogued
in [docs/RUNTIME_FLAGS.md](docs/RUNTIME_FLAGS.md).

On a scheduler host, generate the submission skeleton once with
`tools/generate_submission_template.sh <name>` (`./compile.sh` prints this exact
command for your host). Edit the generated `apps/submission_scripts/<name>.sh`:
**fill in its `#SBATCH` resources, then change the in-file line
`CELEPHAIS_SCHEDULER_READY=0` to `CELEPHAIS_SCHEDULER_READY=1`** (the launcher greps
that file — an exported shell variable is ignored). Re-run the launcher to submit.

## Equations of state

Cold EOS files live in [`data/eos/`](data/eos/): piecewise-polytrope
(`.polytrope` → `Cold_PWPoly`) and tabulated (`.lorene` → `Cold_Table`). Format
and config keys (`eostype`, `eosfile`, `h_cut`, `interpolation_pts`) are in
[data/eos/README.md](data/eos/README.md). Validate a new table before use:

```bash
cmake --preset macbook -DBUILD_TESTING=ON
cmake --build build --target eos_hygiene
./build/tests/eos/eos_hygiene data/eos/<table>.lorene
```

## Testing

```bash
cmake --preset macbook -DBUILD_TESTING=ON
cmake --build --preset macbook
ctest --test-dir build -L unit -L smoke      # fast sanity gate
```

`unit` (Catch2), `smoke` (per-app launch/convergence sanity), and a manual `eos`
diagnostic.
